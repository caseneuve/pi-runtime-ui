## Context

Six remaining production diagnostics are local typing issues rather than one
shared untrusted-input boundary: assertions in `branch-status` and
`runtime-footer`, one widened provider-name dictionary, and a redundant runtime
check over the known `string | null` Git result.

Resolve each at the narrowest owner. Do not invent parsers or abstractions for
values already constrained by internal or pinned upstream types.

## Acceptance Criteria

- [x] At each current assertion diagnostic, remove the assertion where inference
      or a precise upstream/local type suffices; any retained assertion has an
      immediate, accurate `SAFETY:` justification.
- [x] `branch-status` uses the pinned session-entry contract or a minimal
      projection without unchecked widening of `getEntries()`/`getLeafEntry()`.
- [x] Runtime-footer removes avoidable `AssistantMessage`/model assertions and
      keeps provider-shortening inference without an open-dictionary widening.
- [x] `isGitRepo` handles its known `string | null` result directly without a
      representation parser or runtime `typeof` check.
- [x] All six owned diagnostics disappear with no new diagnostic identity.
- [x] Existing behavior and public extension contracts remain unchanged.
- [x] Add behavior tests only if a change can affect session traversal, cost or
      context calculation, Git detection, or rendered output. For demonstrably
      inference-only/nullish cleanup, record why no new test is needed rather
      than manufacturing one.
- [x] Focused tests, `npm run verify`, `npm run test:coverage`, and the anti-slop
      run pass apart from sibling-owned diagnostics.
- [x] Independent review approves this subtask against `AGENTS.md`.

## Notes

- Prefer `satisfies`, inference, and existing Pi message/model/session types.
- This subtask is behavior-neutral. Screenshot review is unnecessary unless the
  implementation changes rendered output, in which case stop and update scope.
- Pinned Pi 0.85.1 `SessionManager` types make `getEntries()` return
  `SessionEntry[]` and `getLeafEntry()` return `SessionEntry | undefined`; use
  that direct contract rather than a local projection. The same pinned
  `ExtensionContext` exposes `Model.contextWindow`, so that footer assertion was
  redundant. `runGit()` already returns `string | null`, so
  `Boolean(topLevel?.trim())` is the equivalent nullish check.
- Pi 0.85.1's `parseSessionEntries()` only JSON-parses entries and
  `SessionManager` indexes them without message-schema validation. Therefore,
  although the static assistant discriminant has required `usage.cost.total`,
  persisted older or hand-edited messages may omit it. Cost accumulation retains
  nullish access with no assertion so those loadable entries contribute zero.
  RED commit `c38048e` adds a parsed, malformed persisted assistant entry and
  proves the previous direct access threw during cost rendering; GREEN commit
  `7761efc` restores the tolerant access.
- `PROVIDER_SHORT` retains its literal object type through
  `satisfies Record<string, string>` and resolves only own declared mappings.
  Focused coverage confirms a documented mapping plus ordinary and `toString`
  custom-provider fallback. The old inherited `Object.prototype.toString`
  lookup was an accidental unsafe function-valued result, not documented custom
  provider behavior; intentionally returning the raw custom ID preserves the
  supported custom-provider contract without an open index signature or cast.
- Focused `runtime-footer`, adapter, and compiled-rendering tests passed (50
  tests). Final checks passed: `npm run check:ci`, `npm run typecheck`, `npm run
  verify` (84 tests), `npm run test:coverage` (84 tests; 72.54% statements), and
  `npm run pack:check` (11 entries). `npm run lint:anti-slop` reports only the
  six sibling-owned test assertions in `test/external-editor.test.ts` and
  `test/package.test.ts`; all six diagnostics owned here are absent.
- Screenshot review is unnecessary: the new coverage proves existing cost and
  provider rendering behavior, and the only provider edge correction prevents
  an unsafe function-valued inherited lookup rather than changing documented
  output. Independent Sol/medium re-review approved the final checkpoint; the
  review is recorded at
  `.reviews/chore-eliminate-remaining-anti-slop-baseline-2026-09-12-202327.md`.
