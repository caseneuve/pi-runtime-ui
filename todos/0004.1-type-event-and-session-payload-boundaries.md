## Context

`editor-status` restores agent identity/comms state from custom session entries
and consumes untyped extension-bus payloads. `runtime-footer` consumes the same
comms event. These boundaries currently propagate `unknown`, perform ad hoc
runtime representation checks or assertions, and account for seven anti-slop
diagnostics.

Establish the smallest coherent payload contracts at the actual external
boundaries. Do not create a general event-schema subsystem.

## Acceptance Criteria

- [x] Add focused behavior tests before production changes for restored identity
      and comms state plus live name/comms event updates in `editor-status`.
- [x] Cover the runtime-footer comms event behavior through its existing
      registered-adapter/render seam.
- [x] Parse persisted custom-entry data and extension event payloads once into
      precise named domain values; downstream state helpers do not accept or
      return `unknown`.
- [x] Invalid, missing, and empty identity/comms payloads retain current fallback
      behavior without throwing.
- [x] Remove the two `no-unknown-parameters`, two `no-runtime-typeof`, and two
      assertion diagnostics in `editor-status.ts`, plus the
      `no-unknown-parameters` diagnostic in `runtime-footer.ts`, with no new
      diagnostic identity.
- [x] Preserve event names, status/editor ownership, render invalidation, and
      subscription disposal behavior.
- [x] Focused tests, `npm run verify`, `npm run test:coverage`, and the anti-slop
      run pass apart from diagnostics explicitly owned by sibling subtasks.
- [x] Independent review approves this subtask against `AGENTS.md`.

## Affected Files

## E2E Spec

GIVEN valid, invalid, and absent persisted agent-channel state and live event
payloads
WHEN editor-status and runtime-footer initialize and receive updates
THEN they preserve current labels/comms rendering and safely ignore or default
invalid representations
AND unparsed values do not propagate beyond the event/session boundary.

## Notes

  `unknown`. `typebox` is a Pi-bundled core package, declared in
  `peerDependencies` as `"*"` and pinned at 1.3.7 in `devDependencies` for
  local type checking. Its `Value.Check` schemas decode those values at the
  session/event boundaries rather than using assertions or representation
  checks downstream.
- `editor-status` has a narrow registration adapter solely to exercise its
  existing editor factory through the same event/subscription lifecycle; public
  event names and default-extension behavior are unchanged.
- RED checkpoint `017fc01` added focused editor-status and footer-adapter tests;
