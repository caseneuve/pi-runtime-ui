## Context

After the diagnostic cleanup subtasks establish a zero baseline, make that
policy an ordinary local and CI gate. The current `verify` script omits
anti-slop, while GitHub Actions invokes individual checks rather than
`npm run verify`, so changing only one command would leave another path open.

## Acceptance Criteria

- [ ] RED checkpoint adds a failing `test/package.test.ts` expectation for the
      intended `verify` command before changing `package.json`.
- [ ] `npm run verify` runs non-mutating Biome checks, typecheck, anti-slop lint,
      and tests in a clear fail-fast order.
- [ ] GitHub Actions invokes `npm run verify` (or an explicitly equivalent set
      including `npm run lint:anti-slop`) while retaining coverage and package
      dry-run checks.
- [ ] Package metadata tests assert that normal verification includes the
      anti-slop gate, preventing silent script regression.
- [ ] `npm run lint:anti-slop`, `npm run verify`, `npm run test:coverage`,
      `npm run pack:check`, and `npx prek run --all-files` pass with zero
      anti-slop diagnostics.
- [ ] Focused isolated local installation and immutable full-SHA Git
      installation pass and include the explicit package resources.
- [ ] Independent review approves the final gate against this todo,
      parent #0004, and `AGENTS.md`.

## Affected Files

- `package.json` — include anti-slop in normal verification.
- `.github/workflows/test.yml` — make CI execute the same zero-baseline gate
  while retaining coverage and package validation.
- `test/package.test.ts` — assert verification-script wiring and manifest behavior.
