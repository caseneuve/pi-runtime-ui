## Context

Six remaining production diagnostics are local typing issues rather than one
shared untrusted-input boundary: assertions in `branch-status` and
`runtime-footer`, one widened provider-name dictionary, and a redundant runtime
check over the known `string | null` Git result.

Resolve each at the narrowest owner. Do not invent parsers or abstractions for
values already constrained by internal or pinned upstream types.

## Acceptance Criteria

- [ ] At each current assertion diagnostic, remove the assertion where inference
      or a precise upstream/local type suffices; any retained assertion has an
      immediate, accurate `SAFETY:` justification.
- [ ] `branch-status` uses the pinned session-entry contract or a minimal
      projection without unchecked widening of `getEntries()`/`getLeafEntry()`.
- [ ] Runtime-footer removes avoidable `AssistantMessage`/model assertions and
      keeps provider-shortening inference without an open-dictionary widening.
- [ ] `isGitRepo` handles its known `string | null` result directly without a
      representation parser or runtime `typeof` check.
- [ ] All six owned diagnostics disappear with no new diagnostic identity.
- [ ] Existing behavior and public extension contracts remain unchanged.
- [ ] Add behavior tests only if a change can affect session traversal, cost or
      context calculation, Git detection, or rendered output. For demonstrably
      inference-only/nullish cleanup, record why no new test is needed rather
      than manufacturing one.
- [ ] Focused tests, `npm run verify`, `npm run test:coverage`, and the anti-slop
      run pass apart from sibling-owned diagnostics.
- [ ] Independent review approves this subtask against `AGENTS.md`.

## Affected Files

- `extensions/branch-status.ts` — two session-entry assertions.
- `extensions/runtime-footer.ts` — two assertions and one widened dictionary.
- `extensions/shared/runtime-status-git.ts` — one known-union runtime check.
- Focused tests only where behavior-bearing logic changes require them.
