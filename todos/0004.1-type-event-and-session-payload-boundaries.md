## Context

`editor-status` restores agent identity/comms state from custom session entries
and consumes untyped extension-bus payloads. `runtime-footer` consumes the same
comms event. These boundaries currently propagate `unknown`, perform ad hoc
runtime representation checks or assertions, and account for seven anti-slop
diagnostics.

Establish the smallest coherent payload contracts at the actual external
boundaries. Do not create a general event-schema subsystem.

## Acceptance Criteria

- [ ] Add focused behavior tests before production changes for restored identity
      and comms state plus live name/comms event updates in `editor-status`.
- [ ] Cover the runtime-footer comms event behavior through its existing
      registered-adapter/render seam.
- [ ] Parse persisted custom-entry data and extension event payloads once into
      precise named domain values; downstream state helpers do not accept or
      return `unknown`.
- [ ] Invalid, missing, and empty identity/comms payloads retain current fallback
      behavior without throwing.
- [ ] Remove the two `no-unknown-parameters`, two `no-runtime-typeof`, and two
      assertion diagnostics in `editor-status.ts`, plus the
      `no-unknown-parameters` diagnostic in `runtime-footer.ts`, with no new
      diagnostic identity.
- [ ] Preserve event names, status/editor ownership, render invalidation, and
      subscription disposal behavior.
- [ ] Focused tests, `npm run verify`, `npm run test:coverage`, and the anti-slop
      run pass apart from diagnostics explicitly owned by sibling subtasks.
- [ ] Independent review approves this subtask against `AGENTS.md`.

## Affected Files

- `extensions/editor-status.ts` — persisted-state and live-event boundaries,
  including both custom-entry assertions.
- `extensions/runtime-footer.ts` — comms event boundary.
- `test/editor-status.test.ts` — focused state/event behavior coverage, if a new
  test file is the smallest seam.
- `test/runtime-footer-adapter.test.ts` — registered footer comms regression.

## E2E Spec

GIVEN valid, invalid, and absent persisted agent-channel state and live event
payloads
WHEN editor-status and runtime-footer initialize and receive updates
THEN they preserve current labels/comms rendering and safely ignore or default
invalid representations
AND unparsed values do not propagate beyond the event/session boundary.

## Notes

- Use the pinned Pi 0.85.1 session-entry and event APIs as the compatibility
  contract before designing local types.
- Tests are required here because boundary decoding can alter visible state.
- Any visible output change is out of scope; if unavoidable, stop and update the
  parent before proceeding.
